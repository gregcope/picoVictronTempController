# Victron Temperature and Fan Controller

MicroPython firmware designed for a Raspberry Pi Pico 2 W to monitor Victron system temperatures using DS18B20 one-wire temperature probes, control dual 12V cooling fans via two standard non-latching relays, and manage secure Over-The-Air (OTA) updates via MQTT and Home Assistant discovery.

## Repository Structure

```

├── boot.py              # Headless boot sequence watchdog, OTA validation and rollback manager
├── main.py              # Core application logic, async loop, hardware drivers and MQTT management
```

## Overview

This project provides thermal monitoring and automated dual-fan cooling for your Victron equipment enclosure. It polls four DS18B20 temperature probes (`InverterBottom`, `InverterTop`, `BatteryCables`, and `VictronLynx`) on a single one-wire bus, applies median filtering and delta thresholds, and publishes telemetry live to Home Assistant.

Based on configurable temperature hysteresis setpoints, it triggers dual relay switches to manage airflow. To ensure absolute equipment protection, it features an immutable hardcoded local safety failsafe independent of network connection state.

## Architectural Decisions and Strict Constraints

* **No Local Logging (Strict Constraint):** Local file logging is prohibited during standard execution to prevent flash memory wear. All diagnostics and telemetry are routed live via MQTT to Home Assistant.

* **Asynchronous Execution (Strict Constraint):** The firmware operates entirely within an asynchronous `asyncio` event loop. Blocking synchronous I/O operations are avoided except during an active OTA download sequence.

* **OTA Validation and Rollback:** Firmware updates are executed seamlessly via MQTT. An `ota_pending.flag` is created before downloading new code. The `boot.py` script acts as a gatekeeper; if the new `main.py` fails to initialise and clear the flag, `boot.py` deletes the corrupted file, restores `main_backup.py`, and resets the hardware.

* **Resilient Network Management:** Employs an exponential backoff retry loop coupled with an eight-second hardware watchdog timer. If Wi-Fi or MQTT communication fails repeatedly, the system backs off before triggering a clean hardware reset.

* **Sensor Noise Reduction:** Implements a three-sample median filter combined with a 0.3°C delta threshold to eliminate raw sensor jitter and prevent excessive MQTT database chatter.

* **Immutable Hardware Failsafe:** The critical safety threshold (`CRITICAL_OVERRIDE_TEMP_C` at 50°C) is hardcoded locally on the device to guarantee thermal protection even if Wi-Fi drops, MQTT stalls, or Home Assistant servers restart.

## Hardware Architecture and Pin Mappings

* **Microcontroller:** Raspberry Pi Pico 2 W

* **Power Supply:** Mean Well APV-8-5 (5V at 1.4A, 8W) power unit feeding the Pico and logic rails.

* **Sensors:** Four DS18B20 temperature probes (`InverterBottom`, `InverterTop`, `BatteryCables`, and `VictronLynx`) sharing a single one-wire bus on **GPIO 15**.

* **Pinout Connections:**

  * VCC (Red): 3V3 (Pin 36) - Power supply (3.3V)

  * GND (Black/Blue): GND (Pin 38) - System Ground

  * Data (Yellow/White): GP15 (Pin 20) - 1-Wire Data Line

* **One-Wire Pull-Up:** Incorporates a 4.7kΩ pull-up resistor between the 3.3V rail and the data line on GPIO 15.

* **Fan Relay Outputs:** Dual standard non-latching relay switches driven via **GPIO 14** (Fan 1) and **GPIO 13** (Fan 2) using straightforward `HIGH`/`LOW` states.

## Agent-Executable Runtime and Timing Specifications

* **Watchdog Timeout:** 8000 ms (eight seconds). The hardware watchdog is fed on every iteration of the main loop.

* **Exponential Backoff Sequence:** Initial backoff is 1.0 second, scaling by a multiplier of two up to a maximum cap of 60.0 seconds.

* **Failure Threshold:** Reaching twenty consecutive failed connection attempts triggers an automatic hardware reset via `machine.reset()`.

* **Sensor Polling Cycle:** Non-blocking 750 ms one-wire conversion delay followed by active task coordination.

* **Fan Relay Switch Topics:**

  * Command: `homeassistant/button/pico_victron_controller_ota/set`

## Required Files for a New Installation

To set up the controller on a fresh device, ensure the following files and packages are placed on the Pico root:

* **`boot.py`**: Headless boot sequence watchdog, OTA validation, and rollback manager (v1.6.4).

* **`main.py`**: Core application logic, async loop, hardware drivers, and MQTT management (v1.6.4).

* **`secrets.py`**: Local operational credentials.

* **`ugit.py`**: Handles over-the-air firmware updates.

* **`umqtt.simple`**: Installed via Thonny's package manager for MQTT communication.

## Step-by-Step Installation Instructions

### Step 1: Install MicroPython Firmware

1. Download the official MicroPython UF2 firmware image for the **Raspberry Pi Pico 2 W**.

2. Hold down the **BOOTSEL** button on your Pico 2 W and plug it into your computer via USB. It will mount as a mass storage drive named `RPI-RP2`.

3. Drag and drop the downloaded `.uf2` file onto the `RPI-RP2` drive. The Pico will flash the firmware and reboot automatically.

### Step 2: Install Required Libraries via Thonny

1. Open Thonny and ensure your interpreter is set to **MicroPython (Raspberry Pi Pico)**.

2. Go to **Tools > Manage packages...**.

3. Search for `micropython-umqtt.simple` and install it directly to your device.

### Step 3: Create and Copy `secrets.py`

Create a file named `secrets.py` on your computer with your local network credentials and save it to the root of the Pico:

```
wifiSsid = "YOUR_WIFI_SSID"
wifiPassword = "YOUR_WIFI_PASSWORD"
mqttBroker = "YOUR_HA_MQTT_IP_OR_HOST"
mqttUser = "mqtt_username"
mqttPassword = "mqtt_password"

```

### Step 4: Configure and Bootstrap `ugit.py`

1. Ensure `ugit.py` is saved in the root of your Pico.

2. Run the following setup commands in the Thonny REPL to link the device to your repository and generate the local configuration:

   import ugit
   ugit.create_config(
   ssid="YOUR_WIFI_SSID",
   password="YOUR_WIFI_PASSWORD",
   user="YOUR_GITHUB_USERNAME",
   repository="picoVictronTempController",
   ignore=\["/README.md", "/secrets.py", "/secrets_example.py", "/config.json", "/main_backup.py", "/LICENSE", "/.gitignore"\]
   )

3. Execute the connection and initial sync command in the REPL to pull down your latest codebase (`boot.py` and `main.py`):

   import ugit
   import network

   wlan = network.WLAN(network.STA_IF)
   wlan.active(True)
   wlan.connect("YOUR_WIFI_SSID", "YOUR_WIFI_PASSWORD")
   ugit.pull_all(isconnected=True)

### Step 5: Final Verification and Boot

1. Press `Ctrl+D` in the Thonny REPL to perform a soft reset.

2. Confirm that the system initializes cleanly without any `ImportError` or missing module exceptions.

Once bootstrapped, all future code changes pushed to your repository can be deployed directly by pressing the "Update Firmware" button within Home Assistant.
